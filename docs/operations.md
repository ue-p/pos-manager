# 当日の運用手順書

学祭当日、レジに立つ部員と運営担当が使う手順です。迷ったら「会計は止めない」「分からない客層は不明」が原則です。

## 開店前チェック（各日）

- [ ] 全端末でアプリを開き、ログインできている（初回だけ通信が必要。以後はオフラインでも開ける）
- [ ] **アプリを更新（デプロイ）した後は、全端末でページを読み込み直している**（ブラウザの再読み込みボタン。古い画面のままだと会計が保存できないことがある）
- [ ] **各端末で、画面上部の「担当」で担当者を選んでいる**（日付が変わると未選択に戻るので、毎日開店時に選ぶ。未選択だと会計できない）
- [ ] **端末の時刻が正しい**（数分ずれていると時間帯別の分析が狂う）
- [ ] 各端末の「設定・出力」→「この端末」でレジ番号が正しい（レジごとに別の番号）
- [ ] **テストモードの紫の帯が、全端末で消えている**（オフラインの端末には切替が届かないので必ず目視）
- [ ] お客さん用画面が表示されている
  - 同じPCの2画面目：「設定・出力」→「この端末で開く」→ 外部モニターへ移動 →「全画面」
  - 別端末（タブレット等）：「設定・出力」に出ているURL（`/display?reg=reg_1` など）を開く（ログイン不要）
- [ ] 全端末の表示モード（ライト／ダーク）が、リハーサルで決めたものにそろっている（下の「表示モード」）
- [ ] レジ画面の在庫数が実物と合っている（違えば「設定・出力」→「価格・在庫」の初期在庫を直す）
- [ ] 価格が正しい（変更すると、それ以降の会計から新しい価格になる。過去の会計は変わらない）
- [ ] 状態バーが「オンライン」「未送信 0件」
- [ ] **エクスポート担当の端末**（1台）と **VR係の端末**（1台）が決まっている
- [ ] エクスポート担当のPCで、Chrome のダウンロード先が共有フォルダの同期先になっている（下の「CSVの保存（エクスポート担当）」）

## 担当の分け方

| 担当 | 台数 | やること |
| --- | --- | --- |
| レジ | レジの数だけ | 会計の入力 |
| エクスポート担当 | 1台 | 30分ごと・閉店時のCSVエクスポートと共有フォルダへの保存 |
| VR係 | 1台 | VR体験の記録（「＋1人」）と、その取消 |

1台が複数の担当を兼ねてもよい（例：レジ1のPCがエクスポート担当も兼ねる）。

## レジ担当者

- **担当者の登録**（運営担当。学祭前と、人が増えたとき）：「設定・出力」→「担当者」で名前を追加する
  - 名前は**呼び名かイニシャル**で登録する（例：「うえ」「Y.U」）。本名は登録しない（個人情報を扱わないため）
  - 名前は後から変えられる。来なくなった人は「無効にする」（削除はできない。過去の記録はそのまま残る）
- **いまの担当者を選ぶ**（各端末。開店時と交代時）：画面上部の「担当」のプルダウンで選ぶ
  - 交代するときだけ選び直す。日付が変わると未選択に戻る
  - 未選択だと会計確定・レジ締めができない（テストモード中も同じ）
- 記録・CSV には担当者のID（`cs_xxxx`）だけが残り、名前は出ない。お客さん用画面にも出ない

## 表示モード（ライト／ダーク）

- **リハーサルで会場の明るさに合わせて表示モードを決め、全端末でそろえる**（明るい会場はライト、暗めの会場や外部モニターはダークが見やすい）
- スタッフの端末：「設定・出力」→「この端末」→「表示モード」で「ライト」か「ダーク」を選ぶ（端末ごとに保存される。「自動」は端末の設定に合わせるので、端末によってばらつく）
- お客さん用画面
  - 同じPCの2画面目：上の設定がそのまま反映される
  - 別端末：URL の末尾に `&theme=light` か `&theme=dark` を付けて開く（例：`/display?reg=reg_1&theme=dark`）

## 会計の流れ（すべてタップ）

1. 商品ボタン（押した回数が個数。カートの −／＋ で調整）
2. 客層（子連れ／学生／大人／その他／**分からなければ不明**）
3. 人数（1〜4人／5人以上）
4. 預かり金（ちょうど／500／1,000／5,000／10,000。複数回押すと加算。間違えたらクリア）
5. 「会計確定」→ お釣りが大きく出る。次の商品ボタンで次の会計へ

- 押し間違えたら、その場で **「直前の取消」** → 入力し直す
- もっと前の会計を取り消すときは「会計一覧」から選ぶ（確認あり。取消は元に戻せない）
## VR体験の記録（VR係）

- VR体験の記録は **VR係の端末1台だけ** で行う。VR体験をした人がいたら、1人ごとに「＋1人」
- 押し間違えたら、**同じ VR係の端末で**「取消」を押す（取消できるのは、その端末で最後に記録した1件。他の端末からは取り消せない）
- **テストモードをオフにすると、VR体験の人数の表示が本番の人数に切り替わる**（テストモード中はテストの記録だけ、オフにすると本番の記録だけを数える）。練習で押した人数が消えたように見えるが、正常

## 営業中

- **30分ごとにCSVをエクスポート**（エクスポート担当。状態バーの「CSV保存」が黄色になったら合図）
  - 「CSV保存」の経過時間は**全端末で共通**。どの端末でも、エクスポート担当が最後に保存してからの時間が出る
  - 手順は下の「CSVの保存（エクスポート担当）」
- 「残りわずか」（黄色）の絵柄は、他のレジと口頭で残数を確認する（オフライン中は他端末の販売が反映されないため）
- 店頭で何か変えたら施策ログに記録する（「設定・出力」→「施策ログ」。プリセットボタンか自由メモ）

## Wi-Fi が切れたとき

- **入力はそのまま続けてよい**。会計は端末に保存され、復帰後に自動で送信される
- 状態バーの「未送信 ◯件」が 0 に戻るまで、**ブラウザを閉じない・ログアウトしない・閲覧データを消さない**
- **オフライン中は、ページを再読み込みしない・タブを閉じない**（開いているタブはオフラインでも動き続けるが、再読み込みや開き直しをすると、通信が戻るまで画面が開けなくなることがある。未送信の会計は端末に残るので、開けなくなっても消えはしない）
- 同じPCのお客さん用画面はオフラインでも動く。別端末のお客さん用画面は復帰まで止まる（会計には影響しない）
- PCが壊れたら：別の端末でログインし、レジ番号を合わせれば続きから入力できる（未送信だった分は壊れたPCの中に残る）

## 閉店時（各日）

1. 全端末で「オンライン」「未送信 0件」を確認
2. エクスポート担当がCSVをエクスポートして共有フォルダに保存
3. レジ締め（「設定・出力」→「レジ締め」）
   - レジごとに、数えた現金の**総額**（釣銭準備金を含む）を入力して記録
   - 差額が出たら、施策ログに理由を書く（例：「お釣りの渡し間違い 100円」）
4. 全端末で「未送信 0件」を確認してから、エクスポート担当が最後にもう一度エクスポートして保存（レジ締めの記録を含めるため）
5. エクスポート担当のPCは、Google ドライブのアイコンで同期の完了を確認してから閉じる（下の「閉店時（エクスポート担当のPC）」）

## CSVの保存（エクスポート担当）

**保存先は1か所だけ**：DA研アカウントの Google ドライブ
「マイドライブ\2026_経営陣\07_商大祭\99_POSデータ保存場所」

ZIP のファイル名は `pos_export_reg_1_20261103_143005.zip` のように、レジ番号と日時（秒まで）が入る。
中身は全レジ分なので、エクスポートは担当の1台だけでよい。

### エクスポートするとき（毎回）

1. 状態バーが **「オンライン」かつ「未送信 0件」** であることを確認する
   - オフラインや未送信があるときは出さない（他の端末の分が入らない、不完全な ZIP になる）。設定画面にも注意が出る
2. 「設定・出力」→「CSVをダウンロード（ZIP）」
3. 共有フォルダに ZIP が入ったことを確認する（下の準備をしたPCなら自動で入る）
   - エクスポートすると施策ログに「CSVをエクスポートした（ファイル名）」が自動で記録され、全端末の「CSV保存」が「1分以内」に戻る

### 事前準備（エクスポート担当のPC。学祭前に1回）

**注意点（先に読む）**
- **Chrome は DA研用のプロファイルを新しく作り、POS のログインとダウンロード先の設定はすべてそのプロファイルで行う**（個人のブックマーク・ログイン・ダウンロード先と混ざらないようにするため）。当日もこのプロファイルの Chrome で POS を開く
- **パソコン版 Google ドライブは「ストリーミング」で設定する**。「ミラーリング」にすると、部のドライブ全体がPCにダウンロードされてしまう
- **DA研アカウントは2段階認証が有効**。ログインのときに確認コードが必要になるので、**コードが届く人と一緒に**作業する（1人で始めて途中で止まらないように、日程を合わせておく）

**手順**
1. Chrome のDA研用プロファイルを作る
   - Chrome 右上のプロファイルアイコン →「追加」→ 名前を「DA研POS」などにして作成する
   - 以降の手順 4〜6 と当日の操作は、**このプロファイルのウィンドウ**で行う（ウィンドウ右上のアイコンで、どのプロファイルか確認できる）
2. 「パソコン版 Google ドライブ」（Google Drive for desktop）をインストールし、**DA研アカウント**でログインする（2段階認証のコードを、コードが届く人に確認してもらう）
3. Google ドライブの設定で、同期の方法を **「ストリーミング」** にする（タスクバーの Google ドライブのアイコン → 歯車 →「設定」→「Google ドライブ」→「ファイルをストリーミングする」）
   - エクスプローラーに Google ドライブのドライブ（例：`G:`）ができるので、次のフォルダが見えることを確認する
     `G:\マイドライブ\2026_経営陣\07_商大祭\99_POSデータ保存場所`
     （**ドライブ文字は環境によって異なる**。`G:` でなければ、エクスプローラーの「PC」に出ている Google Drive のドライブ文字に読み替える）
4. DA研用プロファイルの Chrome で POS を開き、ログインする
5. Chrome の右上「︙」→「設定」→「ダウンロード」を開き、「保存先」の「変更」で上のフォルダを選ぶ
6. 「ダウンロード前に各ファイルの保存場所を確認する」は**オフ**にしておく（毎回フォルダを選ぶ手間と、選び間違いを防ぐ）

**学祭の数日前に：保存先に届くかの確認**
1. テストモードをオンにしてから、DA研用プロファイルの Chrome でエクスポートする（テスト用の ZIP）
2. エクスプローラーで上のフォルダに ZIP が入ったことを確認する
3. **ブラウザ版の Google ドライブ**（別の端末からでもよい）で「99_POSデータ保存場所」を開き、同じ ZIP が届いていることを確認する
4. 確認できたらテストモードをオフに戻す（テスト用の ZIP はそのまま残してよい。中身の会計はすべて `is_test=true` か、本番前のもの）
   - 届かないときは、Google ドライブのアイコンでログイン状態・同期のエラーを確認し、当日までに直す。直らなければ当日は「PCが使えないとき」の手順で手動アップロードする

### 閉店時（エクスポート担当のPC）

- 最後のエクスポートのあと、タスクバーの **Google ドライブのアイコンで同期が完了したこと**（アップロード中のファイルが無いこと）を確認してから PC を閉じる。同期の途中でスリープ・シャットダウンすると、最後の ZIP が共有フォルダに届かない

### 学祭後（エクスポート担当のPC）

1. ブラウザ版の Google ドライブで、最終日の最後の ZIP が「99_POSデータ保存場所」に届いていることを確認する
2. POS の状態バーが「未送信 0件」であることを確認する（プロファイルを消すと、未送信の記録も一緒に消えるため）
3. パソコン版 Google ドライブから **DA研アカウントを切断**する（Google ドライブのアイコン → 歯車 →「設定」→ 歯車 →「アカウントを切断」）
4. Chrome の **DA研用プロファイルを削除**する（Chrome 右上のプロファイルアイコン →「プロファイルを管理」→ 対象のプロファイルの「︙」→「削除」）。POS のログイン状態もこれで消える

### PCが使えないとき（タブレット・スマホから手動でアップロード）

1. タブレット・スマホでアプリにログインし、状態バーが「オンライン」「未送信 0件」であることを確認する
2. 「設定・出力」→「CSVをダウンロード（ZIP）」
   - iPhone / iPad（Safari）：ダウンロードした ZIP は「ファイル」アプリの「ダウンロード」に入る
   - Android（Chrome）：「ファイル」アプリ（または「ダウンロード」）に入る
3. 「Google ドライブ」アプリを開き、**DA研アカウント**に切り替える（右上のアカウントアイコン）
4. 「マイドライブ」→「2026_経営陣」→「07_商大祭」→「99_POSデータ保存場所」を開く
5. 「＋」→「アップロード」→ ダウンロードした ZIP（`pos_export_reg_…zip`）を選ぶ
6. フォルダに ZIP が表示されたことを確認する
   - ZIP を展開（解凍）せず、そのままアップロードする

## 新しい版のアプリが出たとき（画面の保存が有効な場合：D-28）

- 状態バーに「新しい版があります［更新］」が出たら、**会計が終わってから**［更新］を押す（会計の途中は押せない。「会計のあとで更新」と出る）
- 押さなくても、次にアプリを開いたときに新しい版になる。お客さん用画面は、開き直すと新しい版になる
- どの版が動いているかは「設定・出力」→「この端末」→「アプリの版」で分かる

## 緊急時：画面の保存（Service Worker）を外す

新しい版を公開しても［更新］が出ない・古い画面のままになる、などの不具合が起きたときに使う（運営担当。デプロイできる人が行う）。

1. 全端末で「未送信 0件」を確認する（できる範囲で。未送信の会計は端末に残るので消えはしない）
2. 開発用PCで、プロジェクトのフォルダから次を実行する
   ```
   npm run build:no-sw
   npx firebase deploy --only hosting --project dakken2026pos
   ```
3. 各端末でアプリを開き直す（再読み込み）。端末に保存していた画面と Service Worker が消え、通常の読み込みに戻る
   - 消えたことの確認（PC の Chrome）：開発者ツール →「アプリケーション」→「Service Worker」に何も無い
4. この状態ではオフラインで再読み込みすると開けなくなるので、**「Wi-Fi が切れたとき」の「オフライン中は再読み込みしない・タブを閉じない」を守る**
5. 不具合を直したら、通常の `npm run build` で公開し直すと、画面の保存が再び有効になる

## 分析するとき

- 共有フォルダの**いちばん新しい ZIP**（ファイル名の日時が最新のもの）を使う。中身は全レジ分
- ZIP の中身：`sales_lines.csv` / `transactions.csv` / `vr_visits.csv` / `action_logs.csv` / `register_closings.csv`
- 取消・テストの行も入っている。集計では `is_void == False and is_test == False` で絞る
- 日時の列は2つある。**Tableau では `local_datetime`**（`2026-11-03 14:05:22` の日本時間。日時として自動認識される）、**pandas では `timestamp`**（`+09:00` 付き。下の例のように `pd.to_datetime` で使う）
- `action_logs.csv` の `log_type` が `csv_export` の行はエクスポートの記録（施策ではない）。施策の前後比較では `log_type == "manual"` で絞る
- 中身の検査：`python scripts/check_csv.py pos_export_reg_1_YYYYMMDD_HHmmss.zip`

```python
import pandas as pd
lines = pd.read_csv("sales_lines.csv")
valid = lines[~lines.is_void & ~lines.is_test].copy()
valid["timestamp"] = pd.to_datetime(valid["timestamp"])
valid.groupby(valid.timestamp.dt.hour)["amount"].sum()
```
