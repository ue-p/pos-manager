# 学祭シール販売POS 要件定義書

> 原本：`学祭シール販売POS_要件定義書.docx`（Oct 19, 2026 · @peanuts）をClaude Code用にMarkdown化したもの。
> **この文書が仕様の正**。実装上の解釈・追加の決定は `docs/decisions.md` に書き、この文書は書き換えない（原本が改訂されたときだけ更新する）。

## 1. 概要と目的

DA研の学祭出店で使う、シール販売用のWeb POSを作る。目的は次の2つ。

- **会計を速く正確に回す**：ワンタッチで入力でき、複数端末で使え、Wi-Fiが切れても止まらないこと。
- **分析用データを集める**：制作費40,750円を回収できたかを検証し、DA研の発表やDAコンペで使える形で保存すること。

PythonやTableauで、前処理なしでそのまま分析できるデータ形式を最優先で設計する。

## 2. 決定事項・前提

| 項目 | 決定内容 |
| --- | --- |
| 商品 | 案1・案2・案3（各100枚、計300枚）とセット |
| セットの中身 | 案1・案2・案3を各1枚ずつの固定 |
| 価格 | 未確定。設定画面から変更できるようにする（仮：単品200円、セット500円） |
| 支払方法 | 現金のみ |
| 客層区分 | 子連れ・学生・大人・その他・不明 |
| 記録単位 | 1会計＝1グループ。客層と人数を会計ごとに記録 |
| データ保存 | クラウドDB＋共通パスワード＋オフライン時は端末に一時保存（構成A） |
| お客さん用画面 | 同じPCの2画面表示と、別端末での表示の両方に対応 |
| 対応端末 | PCがメイン。スマホ・タブレットでも表示・操作できる |
| バックアップ | 手動のCSVエクスポート＋保存忘れを知らせる表示 |

## 3. システム構成

ブラウザで動くWebアプリとして作り、データはFirebaseのFirestoreに保存する。会計はまず端末内に保存され、通信できるときにFirestoreへ送られる。

同じPCのお客さん用画面は端末内で同期するので、Wi-Fiが切れても動き続ける。別端末のお客さん用画面とダッシュボードは、Firestore経由でつながる。

### 構成図（原本の図をテキスト化）

```
「会計は端末に一時保存してからFirestoreへ同期する」

[レジPC]
  スタッフ入力画面 ──即時同期──▶ お客さん用画面（2画面目）
  スタッフ入力画面 ──確定────▶ 端末内の一時保存（オフライン時も保存）
                                    │
                                    └─自動送信─▶ [Firebase（クラウド）]
                                                  ・Hosting（画面を配信）
                                                  ・Authentication（共通パスワード）
                                                  ・Firestore（会計データ）
                                                      追記のみ・会計IDで重複除去
                                                      │
              ┌──────────出力──────────────┤
              ▼                                        ├─表示内容─▶ お客さん用画面（別端末・レジ番号で紐づけ）
  CSVエクスポート（手動）                              └─読み書き─▶ ダッシュボード（集計・設定／スマホ・タブ可）
  Python・Tableauで分析／バックアップを兼ねる
```

| 要素 | 使うもの |
| --- | --- |
| 画面 | ブラウザで動くWebアプリ（フレームワークは実装時に決める） |
| 配信 | Firebase Hosting |
| ログイン | Firebase Authentication（部員共通アカウント） |
| データ保存 | Cloud Firestore（オフライン永続化を有効にする） |
| 同じPC内の画面同期 | ブラウザのタブ間通信（BroadcastChannel） |
| 分析 | CSVをPython・Tableauで読み込む |

## 4. 画面構成

画面は4つ。スタッフ入力画面以外は、それぞれ独立したURLで開けるようにする。

| 画面 | 使う人 | 主な表示・操作 | ログイン |
| --- | --- | --- | --- |
| スタッフ入力画面 | 部員 | 商品・客層・人数・預かり金のボタン、合計とお釣り、在庫残数、VR体験カウンター、直前の取引の取消 | 必要 |
| お客さん用画面 | 来場者 | 購入内容、合計金額、預かり金とお釣り。会計していないときは商品と価格の案内 | 不要（表示のみ） |
| ダッシュボード | 部員 | 売上、黒字までの残り金額、絵柄別の販売数、時間帯別の売れ行き、購入率（購入組数÷VR体験者数） | 必要 |
| 設定・エクスポート画面 | 運営担当 | 価格と在庫の設定、テストモードの切替、CSVエクスポート、レジ締め、施策ログの入力 | 必要 |

スタッフ入力画面の会計の流れ（すべてタップのみ、文字入力なし）：

1. 商品ボタンを押す（押した回数が個数になる。＋／−で調整可）
2. 客層ボタンを押す（子連れ／学生／大人／その他／不明）
3. 人数ボタンを押す（1／2／3／4／5人以上）
4. 預かり金ボタンを押す（ちょうど／500／1000／5000／10000円。組み合わせも可）
5. 「会計確定」で保存し、お釣りを大きく表示する

客層と人数は入れ忘れを防ぐため必須とし、分からないときは「不明」を押す運用にする。

## 5. 機能要件

優先度「必須」は学祭当日までに必ず入れるもの、「推奨」は時間があれば入れるもの。

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | 会計入力 | 商品・個数・客層・人数をワンタップで入力し、購入時刻とともに保存する | 必須 |
| F-02 | お釣り計算 | 預かり金ボタンからお釣りを計算し、両方の画面に表示する。不足時は確定できない | 必須 |
| F-03 | 取消 | 直前の会計をワンタップで取り消せる。過去の会計は一覧から取り消せる。削除せず取消フラグで残す | 必須 |
| F-04 | 在庫管理 | 絵柄別の残数を表示する。セットは3絵柄を各1枚減らす。残数が足りない商品はボタンを無効にする | 必須 |
| F-05 | お客さん用画面の同期 | 同じブラウザなら端末内で即時同期、別端末ならクラウド経由で同期する。別端末では「レジ番号」で紐づける | 必須 |
| F-06 | VR体験者カウンター | VR体験1人ごとにワンタップで記録する。取り消し可 | 必須 |
| F-07 | CSVエクスポート | 分析用CSVをダウンロードする。バックアップも兼ねる | 必須 |
| F-08 | バックアップ通知 | 最後のエクスポートからの経過時間を表示し、30分を超えたら色で知らせる | 必須 |
| F-09 | テストモード | 練習中の入力にテストフラグを付け、集計と在庫計算から除外する。画面に常時表示する | 必須 |
| F-10 | ログイン | 部員共通のアカウント（メール＋パスワード）でログインする | 必須 |
| F-11 | 価格・在庫の設定 | 価格と初期在庫を設定画面から変更できる。変更前の会計は販売時点の価格のまま残る | 必須 |
| F-12 | 黒字進捗表示 | 売上と「黒字まであと◯円」を表示する | 推奨 |
| F-13 | レジ締め | システム上の現金売上と、数えた現金（釣銭準備金を除く）を照合し、差額を記録する | 推奨 |
| F-14 | 施策ログ | 「POPを変更」などの出来事を時刻付きでメモする | 推奨 |
| F-15 | ダッシュボード | 時間帯別・客層別の売上、購入率を表示する | 推奨 |

## 6. データ要件

分析用CSVは「1行＝1商品明細」のロング形式を主にし、Python（pandas）とTableauで前処理なしに集計できる形にする。

### 6.1 エクスポートするCSV

| ファイル | 1行の単位 | 主な用途 |
| --- | --- | --- |
| sales_lines.csv | 1商品明細 | 商品別・絵柄別・時間帯別の分析 |
| transactions.csv | 1会計（1グループ） | 客層別の客単価、人数と購入枚数の関係、レジ締め |
| vr_visits.csv | VR体験1人 | 購入率の分母 |
| action_logs.csv | 施策メモ1件 | 施策の前後比較 |

### 6.2 sales_lines.csv の列定義

| 列名 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| transaction_id | 文字列（UUID） | 3f2a9c1e-… | 会計ID。端末側で発行し、重複しない |
| line_no | 整数 | 1 | 会計内の明細番号 |
| timestamp | 日時（ISO 8601） | 2026-11-03T14:05:22+09:00 | 会計確定時刻（端末の時刻） |
| item | 文字列 | design_1 | design_1 / design_2 / design_3 / set |
| quantity | 整数 | 2 | 個数 |
| unit_price | 整数（円） | 200 | 販売時点の単価 |
| amount | 整数（円） | 400 | unit_price × quantity |
| design_1_qty | 整数 | 2 | この明細で出ていった案1の枚数（セットは個数分） |
| design_2_qty | 整数 | 0 | 同上（案2） |
| design_3_qty | 整数 | 0 | 同上（案3） |
| group_type | 文字列 | family | family / student / adult / other / unknown |
| group_size | 整数 | 3 | 1～5。「5」は5人以上を意味する |
| register_id | 文字列 | reg_1 | レジ番号 |
| device_id | 文字列 | dev_a1b2 | 入力した端末 |
| is_void | 真偽値 | false | 取消済みなら true |
| is_test | 真偽値 | false | テストモードの入力なら true |

transactions.csv は、会計単位の列（transaction_id、timestamp、group_type、group_size、total、received、change、絵柄別枚数の合計、register_id、device_id、is_void、is_test）を持つ。

### 6.3 共通ルール

- 文字コードはUTF-8。区切りはカンマ。先頭行は英語の列名
- カテゴリの値は英語のコード値にし、画面上の日本語表示とは分ける
- 金額は「円」やカンマを付けない整数
- 取消・テストの行も削除せず出力し、分析時にフラグで除外する
- 空欄は作らない（分からない客層は unknown）

### 6.4 Firestoreの保存構造

| コレクション | 1ドキュメントの単位 | 備考 |
| --- | --- | --- |
| transactions | 1会計 | ドキュメントID＝transaction_id。明細は配列で持つ |
| vr_visits | VR体験1人 | |
| action_logs | 施策メモ1件 | |
| settings | 設定一式 | 価格、初期在庫、回収目標額（40,750円） |
| display_state | レジ番号ごと | 別端末のお客さん用画面への表示内容 |

在庫数と売上は保存せず、取消・テストを除いた全会計から毎回計算する。

## 7. 非機能要件

| 観点 | 要件 |
| --- | --- |
| オフライン耐性 | 通信が切れても会計入力を続けられる。端末に保存し、復帰後に自動で送信する。画面に通信状態と未送信件数を表示する |
| 競合回避 | 会計は追記のみで上書きしない。会計IDを端末側で発行し、二重送信されても同じドキュメントになるようにする |
| 在庫のズレ | オフライン中は他端末の販売が反映されない。残りわずかな絵柄は画面で強調し、口頭で確認する運用で補う |
| 障害時の継続 | お客さん用画面が止まっても、スタッフ入力画面だけで会計を続けられる。PCが壊れても、別端末でログインすれば続きから入力できる |
| セキュリティ | ログインした人だけが読み書きできる（Firestoreのセキュリティルール）。お客さん用画面は表示内容の読み取りのみ。個人情報は扱わない。URLは部外に公開しない |
| 操作性 | 1会計は文字入力なしのタップのみで完了する。ボタンは指で押しやすい大きさ（目安：縦横48px以上）にする |
| 対応環境 | PC、タブレット、スマホの最新ブラウザ（Chrome、Safari）。画面幅に合わせてレイアウトを切り替える |
| 費用 | Firebaseの無料枠（Sparkプラン）の範囲で運用する |

## 8. 運用ルールと未決事項

### 8.1 運用ルール

- 開店前にテストモードがオフになっていることを確認する
- 30分ごと、および各日の閉店時にCSVをエクスポートし、共有ドライブに保存する
- 客層が判断できないときは迷わず「不明」を押す
- 押し間違えたら、その場で「直前の取消」を押して入力し直す
- 各日の閉店時にレジ締めを行い、差額があれば施策ログに理由を書く

### 8.2 未決事項

- [ ] 本番の価格（単品・セット）。唐突な割引きとか
- [ ] 学祭の日程と営業時間（日別の集計をどう区切るか）
- [ ] レジの台数と、当日使う端末（外部モニター・タブレットを用意できるか）
- [ ] 会場のWi-Fi／テザリング環境
- [ ] 釣銭準備金の額
- [ ] 「学生」「大人」の判断基準を部員間でそろえるか
- [ ] エクスポートしたCSVの保存先
